# Ход разработки
## 1. Основа расчёта — завершено
Каталог Hunter, издание 41, стр. 53: 90 табличных сочетаний для MP-1000, MP-2000 и MP-3000 (радиус в метрах, расход в л/мин). Для каждой записи известны сектор и давление на сопле. В руководстве по проектированию разделы на PDF-листах 8–10 описывают перекрытие, деление на зоны и подбор труб. Исходники клиентов и оригиналы PDF хранятся отдельно от кода.
Проверка: node --test tests/catalog.test.mjs.
Следующий этап: загрузка нового изображения, автоматическая разметка и указание масштаба.

## 2. Загрузка изображения и разметка — завершено
Браузер обрабатывает новые JPG, PNG и WebP локально. Выделены связные цветные области; доступны оригинал, наложение, исправление класса и измерение по двум точкам. Распознавание цвета приблизительное. Пример — отдельный синтетический план. Сборка в один HTML: python tools/build.py. Проверка: node --test tests/*.test.mjs.
Следующий этап: предварительная расстановка по подтверждённому масштабу и расчёт расхода.
Синхронизация: GitHub ответил 403 при создании дерева и при записи файла. Коммиты сохраняются в git bundle, журнале и версионном архиве до получения рабочего доступа.

## 3. Эскиз дождевания — завершено
При известном масштабе браузер строит варианты секторов по распознанной маске газона. Выводит примерную площадь покрытия и вылет за газон в кадре. Рабочая точка для эскиза — 2,8 бар непосредственно на сопле. Ввод подачи позволяет предварительно сгруппировать дождеватели. Есть просмотр зон по очереди, ведомость CSV и печать. Подбор сопел пока ограничен стандартными MP. Валидация узлов и труб, смета по остаткам и коммерческая выдача — последующие этапы.
Следующий этап: чтение PDF и надписей, проверка на трёх исходниках.

## 4. PDF, ввод масштаба и прототип для проверки — завершено
24 ноября 2026. Доступ GitHub восстановлен, этапы 1–3 записаны в main, содержимое каждого дерева сверено с локальным Git. Актуальной точкой возобновления служит main.
Браузерная версия открывает первую страницу PDF и читает текстовый слой. Для изображений работает цветовая разметка и поиск периодической сетки. Величину клетки подтверждает пользователь, если на плане не удалось прочитать единицу. На трёх предоставленных примерах выполнена проверка приёма файлов. Светло-зелёный фон и мелкие значки деревьев потребовали поправки к классификации. Количественная оценка правильности границ пока отсутствует.
Серверный вариант включает чтение PDF, OCR и адаптер локальной модели Ollama. В среде проверки был только английский OCR. С моделью и полным русским OCR нужна отдельная проверка. В закрытом прототипе работают браузерные алгоритмы.
Проверено: 6 тестов каталога, разметки и полива; серверные тесты первой страницы PDF и ошибочного ввода; ручная проверка предварительного деления учебного участка на три зоны при 15 л/мин.
Следующий этап: сравнить результаты с готовым проектом инженера (исходник клиента, чертёж, итоговая смета), измерить ошибки классификации и покрытия на новых объектах. Перед коммерческим выпуском остаются трассировка с потерями давления, капельный полив, артикулы/цены, заказ проверки, оплата и отправка на почту.
